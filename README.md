# MOSS-Image 桌面启动器 · 0.1 正式版

面向零基础用户的 Windows 桌面软件，基于 [OpenMOSS/MOSS-Image](https://github.com/OpenMOSS/MOSS-Image)。独立制作的包装器。使用chatGPT生成。

**下载正式版：[v0.1 发布页](https://github.com/RuoLiQwQ/MOSS-Image-Desktop/releases/tag/v0.1)**。普通用户下载其中的 `MOSS-Image-Desktop-v0.1.exe` 即可。

项目源码与问题反馈：[RuoLiQwQ/MOSS-Image-Desktop](https://github.com/RuoLiQwQ/MOSS-Image-Desktop)。

## 第一次使用

1. 双击 **MOSS-Image-Desktop-v0.1.exe**，即可打开独立的中文窗口。无需先装 Python、Git 或 CUDA Toolkit，不需要管理员权限。
2. 进入左侧 **存储设置**，分别选择 **环境与缓存**、**模型**、**生成图片** 的文件夹，可以放在不同磁盘。默认会优先建议空间较多的非系统盘。三个文件夹不能相同或互相嵌套。
3. 保留默认魔搭模型来源，可先点击 **保存设置**；再点击底部 **一键启动**。首次联网自动准备环境、检查电脑、下载并校验模型。窗口显示状态与日志。
4. 准备完成后，会在默认浏览器打开中文创作界面。输入画面描述，再点击 **开始生成**。首次生成还需要加载模型。
5. 下次仍双击同一个 EXE，软件会记住路径并复用已完成的下载。

这是**独立桌面启动器 + 本机浏览器画室**：安装管理和路径选择在桌面窗口完成，实际绘图操作在浏览器完成。模型和生成计算在本机执行。关闭桌面软件会停止其安装和创作服务，仅关闭浏览器不停止服务。

## 新版界面

- **首页**：MOSS 横幅、模型/环境缓存/作品快捷卡片、当前路径和磁盘余量。
- **存储设置**：分别选择三个保存位置和模型下载源，可单独保存设置而不开始下载。
- **运行日志**：集中查看安装、校验和创作服务的输出。
- **使用帮助**：首次使用步骤、目录迁移说明和电脑要求。
- 底部始终显示状态和启动/停止入口，切换页面不影响当前任务。

视觉布局参考秋葉 aaaki 整合包所用的绘世启动器，采用深色侧栏、横幅、快捷卡片和主启动按钮；MOSS 的名称、图形和界面代码独立实现。参考链接见 `UI_REFERENCE.md`。

## 空间怎样分配

| 位置 | 保存内容 | 可否另选磁盘 |
| --- | --- | --- |
| 环境与缓存 | 专用 Python、运行库、下载缓存、临时文件、运行日志 | 可以，例如 `D:\MOSS-Image-Data\data` |
| 模型 | 完整模型与未完成的下载，实际放在所选目录下的 `MOSS-Image-SFT` | 可以，例如 `E:\AI-Models` |
| 生成图片 | 图片和生成参数 | 可以，例如 `D:\MOSS-Image-Data\pictures` |

软件文件本身不必放在模型所在磁盘。少量启动程序和路径设置保存在 `%LOCALAPPDATA%\MOSS-Image-Desktop`；大型环境、模型以及应用管理的缓存放在你选择的位置。Windows 自身的虚拟内存、浏览器缓存和驱动缓存仍由系统管理。

运行中路径设置会暂时锁定。先点击停止，等进程退出后再更换路径。**更换位置不会自动移动或删除旧文件**；如果改到空文件夹，下次会重新下载。

需要搬家时：关闭软件，手动复制原环境与缓存文件夹、模型文件夹到新位置，重新打开软件选择新文件夹。已有模型会校验后复用，环境会尝试刷新其解释器位置；请保留旧目录直到新位置启动成功。模型选项应选择包含 `MOSS-Image-SFT` 子文件夹的上一级目录，避免多套一层目录。

模型、环境和图片位于同一磁盘时，空间需求会合并计算；位于不同盘时逐盘检查。模型下载本身约 27.22GB。建议总计预留至少 **60GB**，并为后续作品额外留出空间。不要手动删除正在运行的缓存或环境文件。

## 电脑要求与下载量

| 项目 | 本软件的适用范围 |
| --- | --- |
| 系统 | Intel / AMD 64 位 Windows 10 22H2（19045）或 Windows 11；不支持 ARM Windows |
| 显卡 | 支持原生 BF16 的 NVIDIA Ampere 或更新架构，例如 RTX 30 / 40 / 50 系列 |
| 驱动 | 本包保守要求 NVIDIA 570.65 或更新驱动；安装后会执行真实 CUDA/BF16 小计算验证 |
| 显存 | 建议 16GB 及以上。8–12GB 仅实验性尝试，可能内存不足或非常慢；不是已确认可用的最低配置 |
| 系统内存 | 本包拦截低于约 16GB 的设备，建议 32GB 或更多。该阈值是包装器策略，不是官方最低配置或成功保证 |
| 磁盘 | 建议准备至少 **60GB 可用空间**；程序按未完成模型和安装余量动态检查，首次同盘约需 47GiB；分盘时会分别检查 |
| 联网下载 | 模型 **27.22GB（25.35GiB）**，另有约 3GB 级环境下载；实际取决于缓存和重试 |

默认采用逐层 CPU 卸载、512×512、50 步、提示词长度 512。降低显存占用会增加系统内存、磁盘交换和等待时间；长提示词超过上限会被截断，可在高级参数调整。上游推荐更大分辨率，本软件优先提供 512 级别的三种画幅用于首次尝试。上游介绍的 5B 是生成骨干规模，**不等于整个模型包只有 5B 参数的体积**。

0.1 正式版按用户完成测试后的发布要求制作。已记录的检查结果及历史验证范围见 [TEST_REPORT.md](TEST_REPORT.md)；这不代表所有 Windows / NVIDIA 设备均可用。

## 网络与重试

- 模型有两个固定版本的官方源。两端文件摘要已比对，切换源不会改变模型版本；已完成文件直接复用。
- 下载中断可重试。支持服务器允许的断点续传；服务器不接受续传时，当前未完成文件会从头下载。
- 上述续传适用于模型文件。环境依赖由 uv 管理缓存，尚未完成的大型运行库下载在重试时可能重新开始；软件日志会显示任务仍在运行及等待时间。
- 文件下载后按 SHA256 校验，失败不会当作成功安装。大文件校验时进度可能暂时不变。
- 魔搭选项只切换**模型**来源。启动工具、Python、Python依赖仍需能访问 PyPI、GitHub 和 PyTorch 官方下载站。
- 完整安装后，环境和模型未损坏时可断网启动。首次打开模型仍依赖所有组件已经下载完整。
- 企业网络如果禁止脚本执行、GitHub或官方依赖源，请联系网络管理员；本包不会绕过组织策略。

## 停止、修复与卸载

- 点击停止，下载进度保留；再次启动会复用已下载文件。关闭窗口会清理本次启动的后台进程。
- 网络中断可重试或切换模型来源。魔搭选项仅切换模型下载，Python 与运行库仍从各自官方站点下载。
- 缺少 DLL / WinError 126 / 1114：安装 [微软官方 VC++ x64 运行库](https://aka.ms/vc14/vc_redist.x64.exe)，更新 [NVIDIA 官方驱动](https://www.nvidia.com/Download/index.aspx)，重启再试。
- 显存/内存不足：保持 512 画幅和省显存配置，关闭其他显卡应用；8–12GB 显存仅实验性尝试，不保证成功。
- 日志在所选“环境与缓存”目录的 `logs` 子文件夹。最初启动看 `bootstrap.log`，安装与画室看 `launcher.log`。
- 卸载前先停止并关闭软件，备份作品。删除 EXE、应用本身的 `%LOCALAPPDATA%\MOSS-Image-Desktop` 文件夹即可移除启动器；选定的模型、环境缓存和作品文件夹由你决定是否删除。

EXE 当前未附加数字签名。具体检查记录见 `TEST_REPORT.md`。

控制接口和画室仅监听本机，未启用公开分享。首次下载会访问指定软件/模型官方来源；不会默认上传提示词和图片。

## 维护与构建

源码包包含 `desktop/Desktop.cs`（Windows 窗口）、`app/storage.py`（路径与分盘检查）、`app/launcher.py`（安装和启动管理）、`app/studio.py`（中文画室）及测试。

在 Windows x64 上运行 `desktop/build.ps1` 可使用系统 .NET Framework C# 编译器重建 EXE。普通使用者只需要 EXE，源码和构建脚本均不需要。源码内的 `Start.cmd` 是维护时的旧浏览器入口，使用包内默认路径；正式桌面使用请双击 EXE，以所选路径设置为准。
